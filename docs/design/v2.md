# Synapse V2 plan

V2 turns the remaining instruction-driven seams into deterministic ones,
starting with retrieval quality. Status: slice 1 shipped as 2.0.0, slice C
as 2.1.0, slice D as 2.2.0, slice E as 2.3.0, and slice A (the eval bench)
after 2.3.0, each with its results below. Slice F (reach) is not started.

## Slice 1: retrieval quality

### Why

- **Filters are approximate.** `--type` and `--project` run after the vector
  search. v1.6.1 widens the search until enough rows pass, which works but
  scans more than needed and still ranks across the whole store.
- **Exact names miss.** Pure vector search is weak on identifiers: `#127`,
  `CloudKit`, file names, error codes.
- **Stale decisions surface.** A Decision note can name what it `supersedes`,
  but the old note stays `active`, so recall keeps offering the replaced
  choice.

### What changes

1. **Store schema v2** (a `meta` table records `schema_version`):
   - `chunks` gains `status` (`active` | `superseded`), `superseded_by`, and
     two nullable provenance columns reserved for sharing, `origin` (which
     store wrote the chunk) and `author`. That avoids a second migration when
     slice E lands.
   - `chunks_vec` becomes `vec0(embedding float[768] distance_metric=cosine,
     project text partition key, source_type text, status text)`. Filters run
     inside the vector search, so they are exact. Searches without a project
     filter still span every partition (verified on sqlite-vec 0.1.9).
   - `chunks_fts`, an FTS5 table over chunk text (`porter unicode61`
     tokenizer, available in the bundled SQLite 3.53).
2. **Upgrade without re-embedding.** `synapse extract upgrade` first copies
   `vectors.db` to `vectors.db.bak-<date>`, then rebuilds `chunks_vec` from
   the stored vectors, builds the FTS index, and sets the schema version. It
   is idempotent. Other commands that see a v1 schema stop and point to it.
   `synapse setup` runs it.
3. **Hybrid recall.** The vector search and an FTS5 BM25 search both run
   with the same filters. Results merge by reciprocal rank fusion (k = 60).
   Output keeps the cosine score for vector matches, so the skill's
   "above ~0.55 is strong" guidance still holds, and labels each hit
   `vector`, `keyword`, or `both`. `--mode vector|keyword|hybrid` defaults to
   hybrid. The v1.6.1 widening loop now serves only `--since`, the one filter
   that still runs after the search.
4. **Supersession.** When `/synapse:extract-session` writes a Decision with
   `supersedes`, it then runs `synapse extract supersede <old note> --by
   <new note>`. That marks the old note's chunks `superseded` in place
   (verified: sqlite-vec updates metadata without re-inserting vectors) and
   sets `status: superseded` and `superseded_by` in the old note's front
   matter (it needs the store's `vault_path`, or the note's full path; it never
   calls the Obsidian CLI). The DB is the authority: a re-embed cannot revive a
   superseded note. Recall hides superseded chunks unless
   `--include-superseded` is passed, and then labels them.
5. **Recall golden set (measurement without agent runs).** `synapse
   recall-check <file>` runs a list of queries with their expected sources and
   reports hit rate at 5 and mean reciprocal rank. The golden file for your
   store stays in the store (it quotes your sessions); CI runs a synthetic
   fixture with a deterministic fake embedder, so no Ollama is needed there.
   Baseline before the upgrade, compare after.

### Done when

- The golden set scores at least as well after the upgrade as before, and the
  exact-identifier queries in it improve.
- A filtered query costs one vector search, not a widening loop.
- A superseded decision stops appearing in default recall and appears,
  labeled, with `--include-superseded`.
- The upgrade leaves a backup, is idempotent, and changes no vector.
- Tests cover fusion, filters, supersession, and the upgrade on the fixture
  store; CI stays green on macOS, Linux, and Windows.

### Results (2026-10-26, the author's store: 1,580 chunks, 2 projects)

Measured on a copy of the store with a 24-case golden set: 8 identifier
cases whose answers came from a text search of the chunks, 12 paraphrased
concept questions, and 4 filtered queries.

| Group | Baseline (v1.6.1, vector) | Slice 1 (hybrid) |
|-------|---------------------------|------------------|
| Overall hit@5 / MRR | 0.833 / 0.792 | **1.000 / 0.910** |
| Identifier | 0.625 / 0.562 | **1.000 / 0.875** |
| Filtered | 0.750 / 0.750 | **1.000 / 1.000** |
| Concept | 1.000 / 0.958 | 1.000 / 0.903 |

- Every baseline miss is now found. The filtered miss was a real bug:
  notes tagged `veilmx` were invisible to `--project VeilMX`.
- One concept question fell from rank 1 to 3 (still a hit). Fusion favors a
  chunk both searches rank moderately over one only the vector search ranks
  first. Weighting the keyword list at 0.3–0.7 restored concept MRR to 0.958
  but lost two identifier hits, so plain equal-weight fusion stays.
- Vector-only mode on the new schema matched the baseline's concept scores
  exactly; the gains come from the keyword index and the exact filters.
- The upgrade rebuilt 1,580 chunks with every vector byte-identical, kept a
  backup, and was a no-op on re-run. Supersession was exercised on a real
  near-duplicate decision pair.
- Supersession itself moved the needle: once that pair's older decision was
  superseded, the DKIM question rose from rank 3 to 2 (concept MRR 0.917,
  overall 0.917), because the stale near-duplicate no longer competed.

Hooks (D), role agents (C), sharing transport (E), agent evals (A), and

## Slice C: role agents

### Why

- **Wave agents work without Synapse's rules today.** Verified 2026-10-26 in a
  headless session with the plugin loaded: the main session sees "Synapse
  rules"; a spawned `general-purpose` sub-agent answered that nothing titled
  "Synapse rules" is in its context. Sub-agents get their own prompt, the
  brief, and the `CLAUDE.md`/`AGENTS.md` hierarchy, not the plugin's
  `SessionStart` context. An implementer therefore never hears the
  validation rule unless the brief repeats it.
- **Right-sizing is persuasion.** The core rules describe model tiers in
  prose; nothing makes a wave use them.

### What changes

1. **Five plugin agents** in `agents/`, invoked as `subagent_type:
   synapse:<role>`. Each body carries the rules its job needs (about 2,000
   characters each), and each ends with a fixed report shape the parent can
   check.

   | Agent | Model | Effort | Tools | Carries |
   |-------|-------|--------|-------|---------|
   | `synapse:implementer` | `sonnet` | medium | everything except `Agent` (one writer, no nested fleets) | Smallest change, reuse existing patterns, stay in the brief's files, run its own validation (run path, expected outcome, failure signal), never commit or push unless told; report files changed, commands run with results, and what is unverified |
   | `synapse:verifier` | `sonnet` | medium | `Read, Grep, Glob, Bash`; no edit tools | Check each claim against evidence, run the stated run path, pass/fail per claim with the evidence, never fix anything; tests may leave their usual caches, avoided where a flag allows |
   | `synapse:researcher` | `sonnet` | medium | `Read, Grep, Glob, Bash` (read-only search), `WebFetch`, `WebSearch`, `ToolSearch` | Answer one question; cite the file or URL for every fact; separate fact from inference; say what could not be found |
   | `synapse:reviewer` | `inherit` | high | `Read, Grep, Glob, Bash` (probes in temp folders only); no edit tools | Adversarial: try to break the change or plan; ranked findings with `file:line`, evidence, and a suggested fix; skip style nits |
   | `synapse:scout` | `haiku` | low | `Read, Grep, Glob, Bash` (read-only search) | Mechanical sweeps (inventories, grep-and-summarize, listing call sites); exhaustive and literal; no judgment calls; flag anything that needs one |

   Tools a build lacks are dropped silently, so every read-only role lists Bash
   for search (some builds ship no Grep/Glob). Bash makes the no-write rule a
   rule, not a guarantee; the eval suite's discipline graders check it.

2. **Reviewer minimum, suggested rather than forced.**
   - *In the parent (core rules):* the reviewer inherits the session's model.
     If the session runs below the frontier tier (Opus, Fable), say once per
     session that reviews work best on a frontier model and offer to pass
     `model: "opus"` (or `"fable"`) for `synapse:reviewer`; follow the user's
     answer for the rest of the session.
   - *In the reviewer:* if it is running on a small-tier model, it says so in
     the first line of its report and recommends a re-run on a frontier model.
3. **Core rules.** The waves table names the five agents. The model-tier prose
   shrinks to "the agents carry their models; pass `model` on a call only with
   a reason (escalation after two failed verifications, the reviewer
   minimum)." New rule: a `general-purpose` agent sees only its brief, so the
   brief must carry the rules it needs. Budget: `core.md` stays under 9,500
   characters.
4. **Doctor.** Warn when `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` is set (every
   role's model is overridden) and note `CLAUDE_CODE_SUBAGENT_MODEL`.
5. **Plugin limits respected.** Plugin agents ignore `permissionMode`,
   `hooks`, and `mcpServers`, so tool limits use `tools`/`disallowedTools`
   only. No agent sets `isolation`; the parent passes `isolation: "worktree"`
   per call when writers could overlap (core rules already say so).

### Eval suite (`evals/`)

Each run is an isolated headless session with only the plugin loaded; fixture
repositories come from a scaffold script (`--scaffold`). Eight cases, each
with an outcome grader, a discipline grader, and a role-dispatch indicator
(`tool_used` on `Agent` with `"subagent_type":"synapse:<role>"`, scored only

  their frontmatter (model, tools, size).

- On the eval suite, 2.1 scores at least as well as 2.0 on every outcome

  role in at least 80% of with-arm runs. Anything short is reported, not

## Slice D: deterministic triggers

### Why

- **Recall depends on the model deciding to call it.** The rules ask for it,
  but nothing guarantees it; a session can repeat a past mistake with the
  answer sitting in the store.
- **Extraction depends on someone remembering.** A session that is archived
  but never extracted is never embedded, so recall cannot find it (two V1
  sessions were in exactly that state until migration backfilled them).

### What changes

1. **Auto-recall hint** (`UserPromptSubmit` hook running `synapse
   recall-hint`). For each prompt it searches the active store (hybrid,
   top 5), keeps hits whose cosine score reaches `min_score`, at most
   `max_hits` (3), and drops hits already shown in this session. It injects
   them as compact pointers marked as navigation, not context. It stays
   silent for prompts under four words, slash commands, harness events such
   as background-task notifications (2.2.1), `[recall] auto =
   false`, and whenever the store, schema, venv, or Ollama is unavailable:
   a hint must never block or break a prompt. Hook timeout 10 s; the
   embedding call gets 3 s.
2. **Pending-extraction reminder** (`SessionStart` hook running `synapse
   pending --hook`). If this project has archived sessions without a
   `.processed` marker, one line says how many and which is latest, and the
   rules say to offer `/synapse:extract-session` once. `[extract] remind =
   false` turns it off. File scan only: no Ollama, no DB.
3. **Config**: `[recall] auto` (default true), `min_score` (calibrated),
   `max_hits` (3); `[extract] remind` (default true).
4. **Rules**: how to treat hints (verify before relying on one; never quote
   them as fact) and the reminder (mention once).
5. **Doctor** reports the auto-recall settings and the pending count.
6. **`EVAL_SYNAPSE_HOME`**: eval runs pass only `EVAL_*` variables into
   their isolated sessions, so this lets an eval point Synapse at a fixture
   home. Documented as eval-only.

### Measurement

- **Calibration (local, no Claude cost).** On the author's store: the 24
  golden queries as positives and 24 everyday prompts unrelated to the store
  as negatives. For each threshold, the share of negatives that would get a
  hint (noise) and the share of positives whose expected source appears in
  the hint (benefit), plus hook latency.
- **Agent evals, hints on vs off.** Four `slice-d` cases run on 2.2 against
  two fixture homes with identical stores; only `[recall] auto` and
  `[extract] remind` differ. Cases: apply a convention that exists only in
  memory; answer a release question that memory settles; an unrelated task
  where no hint may appear; and a session start with an un-extracted
  archive.
- **Regression.** The eight slice-C cases on 2.2 (no store, so the new
  hooks must stay silent) against the 2.1 results.

### Done when

- Calibration picks a threshold where at most 1 in 10 unrelated prompts gets
  a hint, and reports the benefit side honestly.
- With hints on, the memory cases score higher than with hints off; the
  noise case shows no injected hint; the reminder case mentions the pending
  session.
- The slice-C cases show no regression.
- Warm hint latency is reported (p50 and worst case).

### Results (2.2.0)

- **Calibration** on the author's store: 17 of the 24 golden queries are long
  enough to get a hint (4+ words).

  | `min_score` | Unrelated prompts hinted | Golden queries hinted | Expected source in hint |
  |-------------|--------------------------|-----------------------|-------------------------|
  | 0.65 | 4/24 | — | — |
  | 0.675 | 0/24 | 16/17 | 16/17 |
  | **0.70** | **0/24** | **16/17** | **15/17** |

  0.675 had no noise, but the top unrelated prompt scored 0.67, too thin a
  margin. Default: **0.70**. Warm latency of the hook command: p50 0.18 s,
  worst 0.19 s.
- **Agent evals** (Sonnet, 2 runs per case, fixture homes identical except
  the two switches): outcome graders **12/12 with triggers on, 6/12 off.**

  | Case | Off | On |
  |------|-----|----|
  | Flag convention known only to memory: flag name | 0/2 | 2/2 |
  | Flag convention: `FLAGS.md` line | 0/2 | 2/2 |
  | Release question (repo has a `preflight` target) | 2/2 | 2/2 |
  | Unrelated task: done, stays on task | 4/4 | 4/4 |
  | Un-extracted archive mentioned at start | 0/2 | 2/2 |

  The release case does not discriminate: once the fixture had a Makefile,
  the agent found `make preflight` on its own. In the first fixture (no
  Makefile) the agent with the hint checked for the target, did not find
  it, and said so instead of repeating the hint as fact, which is the
  behavior the rules ask for. The hint pays off where the convention lives
  only in memory.
- **Eval limits found.** Traces record `SessionStart` hook output but not
  `UserPromptSubmit` output, so no grader can see a hint; and eval sessions
  cannot read files outside their workspace, so a hint's snippet is all the
  agent sees there. The noise case's absence of a hint is shown by running
  the same prompt through `synapse recall-hint` against the fixture store
  ("no hint"). The first run also showed the pending reminder firing in
  every case that shared the archive's project; the fixture archive now has
  its own project.
- **Regression:** the eight slice-C cases on 2.2 match the 2.1 results
  grader for grader (dispatch 16/16, discipline 12/12, outcome 23/24).
- **Cost** of all slice-D eval runs: about $4.40.
- **Fresh-eyes review** (Fable) found four fail-open gaps, all reproduced
  and fixed with tests: a venv interpreter that cannot start made the hint
  hook exit 1 on every prompt (the re-exec ran before the guard); a slow
  Ollama could hold every prompt for the full 10 s (the embed timeout was
  30 s); a wrong-typed config value crashed doctor and silently disabled
  hints; and a negative `max_hits` dropped a hit. The hint's state file is
  now written atomically. These fixes landed after the agent evals; the
  hook's output on the fixture store is unchanged.

## Slice E: shared memory (small team)

### Why

- **Each member's memory is an island.** A decision one person promoted is
  invisible to a teammate who hits the same question next week.
- **Sharing as-is would leak.** Notes carry home paths, machine names,
  session-local references ("#17", "Wave B", "yesterday's session"), and
  sometimes secrets. Nothing may leave a personal store before the scrub
  gate (the sharing requirements below).

### Model

A **team** is a shared folder plus a local index:

```
<home>/shared/<team>/
  notes/            the shared folder (git checkout, or a path in a synced folder)
    Decisions/  Patterns/  Retracted/
    .synapse-team.toml   team name, schema version
  vectors.db        local index, rebuilt from notes/ by content hash; never shared
```

The folder is the source of truth; the index is disposable. A **transport**
only decides how the folder changes:

| | `git` | `folder` |
|---|---|---|
| `notes/` is | a clone under the Synapse home (or a path the user sets) | a path inside the user's synced folder |
| Publish | commit, then push (after the user's OK) | copy the file in; the sync service carries it |
| Receive | `git pull --ff-only`, then re-index | re-index |
| History, undo | git log, revert | none: retraction moves a note to `Retracted/` |

Both use the same note format, scrub gate, retraction, and index, so a team
can move from a folder to git (or back) by moving the files.

Config, per team:

```toml
[shared.acme]
transport = "git"                     # or "folder"
remote = "git@github.com:acme/notes.git"   # git only
# path = "~/Dropbox/acme-synapse"     # folder: required; git: default <home>/shared/acme/notes
author = "alex"                       # written into every note this member shares
# stores = ["main"]                   # whose recall includes this team; default all
# auto_sync = true                    # background pull + re-index at session start
```

### What changes

1. **Scrub gate** (`synapse share scrub <note>`, `synapse share lint
   <path>`). A deterministic pass with three outcomes per finding:
   - *fixed*: home paths (`/Users/<name>/`, `/home/<name>/`,
     `C:\Users\<name>\`) become `~/`, macOS temp paths `<tmp>/`, and
     links to session notes plain words.
   - *blocked*: secrets (cloud keys, `ghp_`/`github_pat_`, `sk-`/`sk-ant-`,
     Slack `xox*`, private key blocks, JWTs, `.env`-style assignments with
     long values), emails, hostnames and device ids, private IPs.
   - *rewrite needed*: session-local references (bare `#17`, "Wave B",
     "Phase 3" but not a definition such as "Phase 1:", "last session",
     "this session", a day word next to a session word or "we"), the
     user's login name, and text aimed at an agent ("ignore previous
     instructions", piped installers). The share skill rewrites these by
     judgment; the lint then has to pass. A line ending in `<!--
     synapse:allow -->` exempts its rewrite findings, never the others.
   Nothing is written to `notes/` while a blocked or rewrite finding remains.
2. **`/synapse:share`** (skill). Pick notes (by name, by recall, or from the
   last extraction), scrub, rewrite session-local references, show each note
   before and after, and share only the ones the user approves. Then
   `synapse share add` copies them in with provenance front matter
   (`origin: <team>`, `author`, `shared_at`, `source_id`) and, for git,
   commits; the skill asks before every push. Re-sharing an edited note
   updates the shared copy by `source_id` lineage instead of adding a
   second one. The file name is scrubbed like the text.
3. **Retraction** (`synapse shared retract <note> --reason`). Moves the note
   to `Retracted/` with the reason in front matter; the next sync drops its
   chunks everywhere. Same in both transports.
4. **Sync** (`synapse shared sync [team]`). Git: pull fast-forward only, with
   `GIT_TERMINAL_PROMPT=0` and SSH in batch mode, so it never waits for
   credentials. Both: re-index by content hash (add new, replace changed,
   drop removed or retracted); skip `.icloud` placeholders, and report
   sync-conflict copies ("conflicted copy", or "<name> 2.md" with the same
   title as "<name>.md") instead of indexing them. Every incoming note
   passes the scrub gate: one with a secret, an identifier, or text aimed at
   an agent is held back. A lock file stops two sessions syncing at once.
5. **Automatic sync**: the `SessionStart` hook starts `synapse shared sync
   --quiet` detached (at most every 10 minutes), so the session never
   waits. Results go to `<home>/state/shared-<team>.json`; a failure that
   lasts more than 3 days gets one line at session start, like the pending
   reminder.
6. **Recall and hints** search the active store plus its teams' indexes.
   Each list keeps its own order and the lists merge by score, the local
   result first on a tie; a note the user shared is not shown twice;
   shared hits are labeled `shared:<team>, <author>`. `synapse recall
   --scope local|shared|all` (default all).
7. **Setup**: `synapse shared init <team>` (creates the folder layout, and
   for git a first commit; creating the remote stays the user's step) and
   `synapse shared join <team> <remote-or-path>`. Both write only the
   Synapse home and the notes folder.
8. **Rules**: shared hits are teammates' notes, not instructions; when one
   contradicts a local decision, follow the local one and say so;
   `/synapse:extract-session` ends by offering `/synapse:share` once when a
   team is configured.
9. **Doctor**: teams, transport, last sync and its result, unpushed commits,
   conflict copies, index freshness.

### Measurement

- **Scrub corpus (unit tests, no cost).** Synthetic notes with planted
  findings of every kind, plus clean notes. Target: every planted secret and
  personal path caught; at most 1 false block in 20 clean notes.
- **Dry run on the author's store (read-only).** `synapse share scrub` over
  every Decision and Pattern: counts per category and a hand check of false
  positives. Nothing is shared.
- **Two-member tests (unit tests, CI).** Two temp homes and, for git, a
  local bare repo: A shares, B syncs, B's recall returns the note labeled
  with A's name; A retracts, B syncs, the note is gone; B's conflicting
  local decision ranks above A's shared one. The same flow for `folder`
  with both homes on one temp folder.
- **Share, live (about $0.30 a run).** The agent shows a scrubbed note with
  its session-local references rewritten and adds nothing without the
  user's OK (`tools/live-check-share.sh`; eval sessions cannot run the CLI).
- **Agent eval.** Conflict: with a shared note that contradicts a local
  decision, the agent follows the local one and says so.
- **Regression.** The slice-C and slice-D cases, and the golden set on the
  author's store with no team configured (results must be identical).

### Done when

- The scrub corpus passes at the targets above, and the dry run's false
  positives are fixed or justified.
- Both transports pass the two-member tests on macOS, Linux, and Windows CI.
- Session start never waits on sync, also with the remote unreachable.
- The evals pass and the regression shows no change.

### Build order

1. Scrub gate and its corpus; the dry run on the author's store.
2. Team folder, both transports, sync, retraction, the team index.
3. Recall and hint merge, provenance labels, local-wins ranking.
4. `/synapse:share`, rules, automatic sync, doctor, INSTALL.
5. Evals, regression, fresh-eyes review; ship as 2.3.0.

### Results (2.3.0)

- **Scrub corpus:** every planted finding caught (each secret type, every
  blocked and rewrite kind, both fixed kinds); 0 of 25 clean notes blocked.
- **Dry run on the author's store** (125 Decisions and Patterns, nothing
  shared): no secrets, emails, host names, device ids, or home paths. The
  first rules flagged 12 notes, about half wrongly: "today" and "yesterday"
  are product vocabulary there ("today's chores", "the Today widget"), and
  "Phase 1:" defined a step in a pattern. Day words now count only next to
  a session word or "we", and "Phase N:" is exempt. Final: 7 notes flagged,
  all correctly (bare issue numbers such as `#59`, and "this session").
- **Two-member tests** (git through a local bare repo, and a synced folder):
  share, sync, update by lineage, retract, conflict copies, iCloud
  placeholders, local-first ranking, and dedupe all pass; 92 unit tests in
  all, on macOS, Linux, and Windows CI.
- **Share, live** (headless sessions, this repo as the plugin, 2 runs):
  both rewrote `#17`, the home path, and "this session", showed only the
  changed lines, and asked before adding; the team folder and the original
  note were untouched. Approving one run added a clean copy with provenance
  and no session id.
- **Conflict eval** (Sonnet, 2 runs): 2/2 followed the local decision and
  named the teammate's contradicting note (6/6 judge votes).
- **Regression:** slice-C cases match 2.1 grader for grader (dispatch
  16/16, discipline 12/12, outcome 23/24); slice-D cases 12/12, as in 2.2;
  the golden set on the author's store with no team is identical to 2.2.1
  (hit@5 1.000, MRR 0.910), and so are spot `synapse recall` results.
- **Found by use, fixed with tests:** `join` read a bare repo as a synced
  folder; a bare repo whose default branch was never pushed cloned empty;
  `shared init` ran twice when the CLI re-executed under the venv after
  writing the config (the eval-home build hit it).
- **Eval limits found:** eval sessions get no plugin `bin/` on PATH, and
  their sandbox cannot read the Synapse home; run from inside a Claude Code
  session, PATH also carried the installed Synapse. Hence the live check for
  the CLI-driven share flow, and `run-evals.sh` now drops installed copies
  from PATH.
- **Cost:** evals $2.81, live checks $1.50.
- **Fresh-eyes review** (Fable) found eleven confirmed problems, all fixed
  with tests: `retract` accepted any file on disk; `join` wrote any team
  name into the config (one with `../` cloned outside the home and broke
  the config); a git team whose folder was not its own clone pulled,
  committed, and pushed the enclosing repository; teammates' notes were
  indexed without a scrub (now the inbound gate) and their `author` field
  rendered raw in hints; rank-by-rank merging let a 0.15 shared hit
  displace 0.66 local ones (now a score merge) and missed own-note dedupe
  outside the top-k (now checked against the local DB); scrub missed
  `file://`, WSL, `/Volumes`, Sessions/ links, Bearer tokens, webhook URLs,
  short passwords, `<name>s-mbp`, and IPv6 link-local addresses; a shared
  file name was not scrubbed; a newline in `--author` or `--reason` could
  inject front-matter keys; a real note named "Use Swift 6" was taken for a
  sync copy; one broken team table silenced local hints; and the
  unreachable-remote test never attempted a pull. Git now also refuses
  askpass and credential-manager prompts. On the author's notes the
  widened scrub flags the same 7 notes. After the fixes: 101 unit tests
  pass, the conflict eval is again 2/2, and the live share check 2/2. The
  slice-C and slice-D cases were not re-run: with no team the merge returns
  the store's own list unchanged, which the retrieval tests cover.

### Not in slice E

Sharing session archives, a server or MCP endpoint (F), pull-request review

beyond the git host's or sync service's, encryption at rest, and more than

## Slice A: eval bench with a no-plugin baseline

### Why

The suite grew slice by slice (role agents, triggers, teams), and each slice
was measured against the previous Synapse. Nothing yet measures Synapse
against no Synapse, and the core loop (verify before reporting, the emission
contract) has no case at all.

### What changes

1. **Baseline arm.** Every case runs with the plugin and without it
   (`claude plugin eval --ablation with-without`). Graders that only mean
   something with Synapse (it dispatched `synapse:<role>`, it offered a
   frontier reviewer) carry `arm: with-only`: reported as a sign the plugin
   fired, not scored. Everything else (outcome, discipline) scores in both
   arms, so the delta is what Synapse adds.
2. **Two core cases** (tag `core`): *verify-before-done* (make a failing
   test file pass; outcome: the whole file passes in the agent's own run)
   and *answer-first* (a fix whose reply should lead with the result and
   end without offers or filler; the emission contract's job).
3. **The release-gate case discriminates.** The fixture no longer carries
   a `preflight` target, so the release convention lives only in memory;
   the grader accepts a reply that names the preflight step (or its pending
   migrations check) even when it notes the target is missing here.
4. **`tools/run-bench.sh --yes`**: builds the fixture homes, runs each tag
   with its home in both arms, keeps reports local, caps cost, and prints
   the report. **`tools/eval-report.py`**: with vs without per case and per
   grader, and a before/after comparison of two runs.

### Measurement and done when

One bench run on 2.3 (2 runs per case, both arms, about $6, capped at $13.50). Done
when every case has a baseline, the report shows the delta per case and in
total, with-only graders are excluded from scores, the release-gate case
separates hints on from off, and the results (including cases where the
baseline does as well) are recorded here.

### Results (Synapse 2.3.0, Sonnet sessions; reviewer-minimum on Haiku)

Mean score over the 15 cases that count in both arms: **1.00 with Synapse,
0.71 without** (+0.29). Every case passes with Synapse.

| Case | With | Without | What decides it |
|------|------|---------|-----------------|
| memory-flag-convention | 1.00 | 0.00 | The team's flag convention exists only in memory |
| memory-release-gate | 1.00 | 0.00 | The preflight step exists only in memory |
| memory-pending-reminder | 1.00 | 0.00 | Only Synapse knows the archive was never extracted |
| team-conflict | 1.00 | 0.00 | Only Synapse sees the teammate's contradicting note |
| general-purpose-brief | 1.00 | 0.67 | Without the rule, briefs omit the validation step (0/2) |
| answer-first, verify-before-done | 1.00 | 1.00 | Sonnet already leads with the result and verifies |
| implement-with-validation, scope-discipline, review-planted-bug, research-with-citation, scout-inventory, verify-claims, reviewer-minimum, memory-noise-unrelated | 1.00 | 1.00 | The baseline does the task as well without role agents |

- **What Synapse adds, measured:** memory (the four memory cases) and the
  general-purpose brief rule. The role agents, the emission contract, and
  the verify-before-reporting rule match a capable model's defaults on
  these tasks; their case for staying is cost (smaller models per role),
  consistency, and larger tasks than this suite holds, which it does not
  yet measure.
- **Signals (not scored):** with Synapse, every role case dispatched its
  `synapse:<role>` agent (14/14 runs); on Haiku, the frontier-reviewer
  offer appeared in 2 of 4 runs.
- **The release-gate case now separates the arms** (2/2 vs 0/2), where the
  2.2 version did not.
- **Found while building:**
  - `claude plugin eval` scores `arm: with-only` graders when a case has
    nothing else. Marking `suggests-frontier` made reviewer-minimum such a
    case, so the CLI credited Synapse +1.0 for its own rule. The case now
    also has a scored `finds-bug` grader, and `tools/eval-report.py` scores
    only the graders that count.
  - The Fable review found further problems, all fixed with tests or by
    removing the check:
    - The report hid errored and cost-skipped runs.
    - The mean compared unpaired cases.
    - A regex grader passed on the diagnostic run before the fix, and
      failed under pytest.
    - The bench reused a half-built fixture home.
- **Cost:** bench $4.63, checks and the rerun of three changed cases $0.96.
  The plugin itself is unchanged (no runtime file), so no version bump.

## Sharing requirements (small team), for slice E

Captured before slice B so the earlier slices would not paint E into a
corner; slice E (above) implements them.

- **Scrub gate.** Before anything leaves a personal store: generalize
  session-local references (bare `#17`, "Wave B", "yesterday's session"),
  replace paths and machine ids with placeholders, and scan for secrets.
  Judgment in extraction, plus a deterministic pass and a lint in the share
  step.
- **Review to share.** Sharing is opt-in per note, never automatic.
- **Provenance.** Every shared chunk carries `origin` and `author` (reserved
  in schema v2), so readers can weigh it and a bad entry can be traced and
  pulled.
- **Local wins.** A member's own store outranks the shared one on conflict;
  shared hits are labeled in recall.
- **Transport, decided in E.** A shared folder of scrubbed notes, changed
  through git or a sync service, with each member rebuilding the index
  locally. An MCP server (F) stays the option for clients outside Claude
  Code.

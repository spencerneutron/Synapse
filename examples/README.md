# Examples

Real planning files from a Synapse session, lightly sanitized (machine paths,
simulator ids, and private links replaced with `<placeholders>`). Read them for
the shape a mature `PLAN.md` / `EXECUTION.md` grows into, not for their content.

| File | What it shows |
|------|---------------|
| `planning/PLAN-choreganize-1.9.md` | Standing rules carried across resets, a pointer to archived history, two stacked initiatives, a "verified facts" block, and a dated Decision Log whose entries carry reusable insights |
| `planning/EXECUTION-choreganize-1.9.md` | One active task: where its branches stand, a dated progress log, the outcome of a user review, and a `Next` checklist that names who owns each step |

They come from an iOS app project, so they mention project-specific skills
(`/deploy`, a roadmap sync) that are not part of Synapse. In Synapse those
belong in a project's own `.claude/skills/` and its PLAN's `## Session hooks`
section.

Blank starting points are in `../templates/`.
